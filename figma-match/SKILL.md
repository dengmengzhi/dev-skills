# Figma UI 1:1 还原

核心原则：**测量代替目测，真值表驱动修改**。每一处改动都要能回答"Figma 是多少、实测是多少、改成多少"。

## 输入

开始前确认下面四项，缺了就问用户，不猜：

1. 组件文件路径（或页面路由，由我定位组件）
2. PC frame 的 nodeId（`134:941` 冒号格式；URL 里是 `134-941`，要转成冒号）
3. H5 frame 的 nodeId。只给了一端的 nodeId 时按场景分流（判定依据：目标组件/页面在仓库里是否已有实现）：
   - **新需求 / 新增页面**（无既有实现）：两端分叉都建立，未给稿的那一端按给稿端**等比推导**，推导值进真值表并标注"推导"，报告里单列
   - **既有页面 / 迭代需求**（已有双端实现）：**只改给稿的这一端，另一端一行不动**，收尾回归另一端未变
4. 本地访问路径 + 前置状态（是否需登录、是否要进入某个特殊态）

## 流程

### 1. 建立双端真值表

- 先加载 `figma-design-to-code`：本项目 Skill 工具里没有它，读 MCP resource `skill://figma/figma-design-to-code/SKILL.md`；之后调 `get_design_context` 时 skillNames 传 `resource:figma-design-to-code`。
- `get_metadata` 确认 nodeId 指向的是目标 frame。用户给的节点常是子元素（一条分隔线、一个渐变矩形），是子元素就上溯到父级 frame 再取上下文。
- PC、H5 各调一次 `get_design_context`，整理成真值表，每行一个元素。新增页面只有一端稿时，另一端按容器宽度比例（如 PC 1440 → H5 375）推导尺寸与间距，字号/行高按项目该端既有档位就近取，颜色/圆角原值沿用；既有页面只有一端稿时，真值表只建这一端：

  | 元素 | 尺寸 | 坐标/间距 | 字号/行高/字重 | 颜色 | 圆角/边框 | 状态（默认/hover/空/加载） |

- `get_screenshot` 只作辅助。带 mask/blur 的节点（视频背景、渐变遮罩）服务端渲染返回 1×1 空图，此时只信 design_context 里的 token。
- 图标/图片用导出资产，不自绘、不用占位图。资产 URL 约 7 天过期，要落仓库就下载到 `public/` 或换项目图片域。

### 2. 扫描组件

- 读组件源码与关联样式，弄清 PC/H5 分叉方式：`useMobile()` 条件渲染、CSS 显隐、还是独立组件。后续改动沿用同一方式。顺带核对 CSS 断点前缀（`md:`/`lg:`）与 JS hook 的阈值是否一致，不一致只记遗留项。
- 列出数据驱动元素（昵称、人数、标签、副标题等），核对接口是否有对应字段。没有字段就在报告里标注，**不硬造假数据**，需要就问用户是否加字段。
- 启动 dev server `npm run dev:test`（端口 3000）。playwright 分别 `resize` 到 PC 宽和 H5 宽（375）截图，并用 eval 读 `getBoundingClientRect()` 和 `getComputedStyle()` 采集实测值。截图存 scratchpad，不落仓库。

### 3. 逐项对照

- 真值表每行对比实测值，产出差异表：

  | 元素 | 端 | Figma | 实测 | 差值 |

- 只记实差，误差 ≤1px 视为一致。
- Figma 明显不合理（语义不对、双端互相矛盾）先问用户，不盲抄。用户倾向"语义正确 + PC/H5 一致"。
- 服务端驱动的特殊态（禁言、已结束、被移出等）客户端触发不了，可在组件里临时加 `?force<state>` 的 query 覆盖状态来渲染，每处标 `// TEMP`。`force` 只用于切换**接口已有的状态值**，不用于伪造接口没有的字段（如没有 vip 字段就不加 `?forcevip`），后者属于硬造数据。
- 对照过程中发现与差异表无关的存量问题（断点错位、命名、旧样式），写进报告第 4 段遗留项，本轮不改。

### 4. 修正

- 只改差异表里有的行，不顺手重排无关代码。
- PC/H5 共用组件的改动**必须用 mobile 条件隔离**，一端改完验证后再改另一端。新增页面只有一端稿时：先改有稿端并验证，再按推导值改另一端，两端分叉都保留。既有页面只有一端稿时：只碰给稿端的分支，另一端分支不进 diff。
- 颜色、字号、间距优先复用项目已有 token（`globals.css` 的 `@theme inline`）和公共组件，不新造平行值。
- 样式改完浏览器没变化：先 eval 读渲染出的 className 或 computedStyle 是否为新值。是旧值就是 HMR 失效，执行 `lsof -ti:3000 | xargs kill -9` 后重启 dev server，不要反复等。

### 5. 验证

- 两端重新截图、重新测量，差异表每行归零或写明保留原因。
- 回归另一端：与改动前截图和测量值对比，确认未变。
- 撤掉 TEMP hack：grep `TEMP` 确认 0 残留。清理 scratchpad 截图，`ls *.png` 确认仓库根目录无残留。
- 自检：`pnpm typecheck` + `pnpm lint <改动路径>`，无新增报错。

### 6. 输出报告

固定四段：

1. 改动文件清单
2. 差异表（修前 → 修后，含 PC/H5 两端）
3. PC/H5 互不影响的证据（另一端测量值改前改后一致）
4. 遗留项：接口缺字段、Figma 不合理项及用户决定、跳过的检查

输出后停手，**不执行 git commit**，用户自行 review 提交。

## 红线

| 冲动 | 应该 |
| --- | --- |
| "截图看着差不多了" | 用 eval 测数值，差值写进表 |
| 直接粘 get_design_context 返回的 React+Tailwind | 只当参考，映射到项目 token 与已有组件 |
| PC/H5 一次改完省事 | 一端改完、回归另一端未变，再改下一端 |
| 接口没字段先写死示例值 | 报告标注，问用户 |
| "这个位置固定是主播，金色算槽位样式不算 VIP 数据" | 设计稿标的是 VIP 态，接口无字段就是没有依据，不上色 |
| "顺手把这个真 bug 也修了" | 不在差异表里的不改，写进遗留项 |
| 新页面只给了 PC 稿，"H5 这轮先不动" | 新页面两端都做：H5 按 PC 等比推导，分叉保留，推导值标注 |
| 既有页面只给了 PC 稿，"H5 顺手也缩一下" | 既有页面只改 PC，H5 一行不动并回归 |
| 图片没资产先放占位 | 用导出资产，拿不到就问 |
| Figma 这样画就这样抄 | 语义不对先问，用户要的是正确不是像 |
| 改完 HMR 没反应再等等 | 读 className 判定，旧值直接重启 3000 |
