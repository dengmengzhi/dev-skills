# 页面动效推荐与预览

核心原则：**先分析再推荐，先预览再落地，方案由用户选**。动效服务于页面层级与品牌气质；默认取向是**效果明显、有冲击**，用户要一眼看出页面"动起来了"，宁可先给足再由用户减，不做看不出来的微动效。**单次只做一端**（PC 或 H5），另一端需要时另起一次。**推荐先查本地配方库**（`library/`），库够用不联网。

## 输入

开始前确认，缺了就问：

1. 页面在哪：URL / 路由 / 组件文件 / 截图（任一即可）
2. 端：PC 还是 H5。用户没说就问，不默认、不两端一起做
3. 范围：整页还是某个区块
4. 约束：目标浏览器与设备、性能预算、是否已有动效库、品牌上有无禁忌（如金融类避免弹跳）

## 流程

### 1. 分析页面结构

- 能跑起来就用 playwright 按所选端的视口抓一张截图（PC 常用 1440 宽，H5 用 iPhone 设备模拟），再读页面源码；只有截图就基于截图分析。
- **先核对配色方案再取色**：playwright 默认按浅色模式渲染，页面若响应 `prefers-color-scheme` 或带 `data-theme` / `.dark` 类，浅色下取到的底色和文字色是错的。用 `page.emulateMedia({ colorScheme: 'dark' })` 各渲染一次对比；两种不一致时以**用户截图或用户描述的可见状态**为准，都没有就问用户。取到的底色、文字色、强调色写进结构表下方，后续预览页原样使用。
- 摸清现状：grep `@keyframes`、`transition`、`animation`、动效库引用（framer-motion / motion / gsap / react-spring / Vue `<Transition>` / lottie），已有的动效语言要延续而不是另起一套。
- 产出结构表，每行一个区块，只列所选端可见的区块：

  | 区块 | 类型（导航/首屏/列表/卡片/CTA/表单/弹层/页脚） | 视觉权重（高/中/低） | 内容性质（静态/数据驱动/媒体） | 当前动效 |

### 2. 判定 UI 风格，定动效语言

从色板、字体、圆角、阴影、留白密度判定风格，映射到一套动效参数，全页统一：

| 风格 | 时长档 | 缓动 | 典型手法 | 避免 |
| --- | --- | --- | --- | --- |
| 深色/奢华/赛事娱乐 | 400–800ms | ease-out、cubic-bezier(0.22,1,0.36,1) | 辉光、流光、视差、慢速渐显 | 弹跳、过快 |
| 活泼/消费/年轻 | 250–500ms | spring、back-out | 弹性缩放、错落入场、图标微动 | 大面积模糊 |
| 企业/工具/后台 | 150–250ms | ease-in-out | 淡入、轻位移、骨架屏、状态过渡 | 装饰性动画 |
| 内容/阅读/资讯 | 200–400ms | ease-out | 滚动渐显、图片渐进加载、hover 抬升 | 持续循环动画 |

通用规则：只动 `transform` 与 `opacity`；同类元素错落间隔 60–100ms；一屏同时运动的元素不超过 3 组；代码里带 `prefers-reduced-motion` 降级（只对开了系统"减弱动态"的用户生效，不影响默认效果，预览里也不展示）；首屏入场动画不阻塞 LCP。H5 端不推荐 hover 类动效，用点击反馈或入场提示替代。

### 3. 推荐清单（先查库）

候选来源按顺序，前一步够用就不走下一步：

1. **只读** `library/index.md`，按结构表里的区块类型 + 第 2 步判定的风格 + 所选端筛出候选 id。
2. 到索引指向的分类文件里取 `### <id>` 到下一个 `### ` 之间的段落（sed/awk 范围截取），不整库读。
3. 库里候选不够 3–6 个、或用户明确要"库里没有的新手法"，才联网搜索。搜到的手法占推荐清单里的一个槽位，计入 3–6 个之内。按 `library/_template.md` 整理成配方段；**用在常规版的新手法先问用户"是否入库"**，同意才写；**用在冲击版的新手法默认直接入库**（见下"配方库"）。

按视觉权重从高到低挑 **3–6 个**区块，每个给主推荐 + 一个备选，表里带配方 id：

| 区块 | 动效（配方 id） | 触发（入场/滚动进入视口/hover/点击反馈/数据变化/路由切换） | 时长/缓动 | 性能标记（仅合成层 / 触发重排） | 优先级 |

低权重区块默认不加动效，写明理由。数据驱动区块主推荐必须来自 `data.md`；备选可以是整块进入视口渐显这类非装饰动效，不推荐装饰动画。配方里的时长/缓动是默认值：与第 2 步风格档冲突时，配方说明里写了例外就按说明，没写就压进风格档。

再把这些配方组合成 **3 套整体方案 = 两套常规版 + 一套冲击版**：

- **常规版 ×2**：都在风格档内，纯 CSS + 少量 JS 能落地，两套按手法路线区分（如 揭示路线 / 流光路线），强度都要肉眼可见，不出"克制到看不见"的版本。
- **冲击版 ×1**：视觉冲击更强、允许叠加更多配方、允许持续性氛围动效（`ambient.md`，每页最多一处）和实现成本更高的手法（3D 倾斜跟随、canvas、动效库编排）。仍守通用规则底线（只动 transform/opacity 或独立 canvas 层、reduced-motion 降级、不阻塞 LCP、离开视口暂停持续动效）。**必须写成本**：新增代码量或依赖体积、持续 GPU/CPU 开销、兼容与降级。

每套写方案名、一句话气质、包含的配方 id。同一区块在三套里可以用不同配方，也可以某套不加。

记下本轮**已展示配方 id**（三套方案里出现过的都算），供"换一批"排除。

### 4. 生成 demo 预览

- 写一个独立 HTML（不依赖项目构建），按所选端的视口宽度，用页面的真实色板、字体、圆角复刻**整个模块**的简化骨架，不拆成逐区块的小面板。**保持现有 UI**：背景色、色板、字体、布局、元素样式都与线上一致，只加动效不改观感；除非用户明确说可以改整体背景或配色。预览页自身的外壳（方案头部、开关）也跟随页面的明暗基调。
- **一次展示 3 套整体方案**（两常规 + 一冲击，冲击版明确标注「冲击版」并把成本写在该套脚注），上下排列，每套是完整模块复刻并挂上该套全部配方，让用户看到的是"上线后整体是什么感觉"。每套头部写方案名、气质、配方 id。
- 每套方案一个 **"原始 / 动效"开关**（原始态 = 同一份骨架不挂任何动效，默认显示动效态，切一下就能对比加与不加）和"重放"按钮；页面级一个"全部重放"。不放 reduced-motion 模拟开关。只复刻所选端，不做双端切换。
- 外链图片通常被预览环境拦截，用 CSS 形状或 data URI 代替。
- 有 Artifact 工具就发布成页面给用户链接；没有就写到 scratchpad 并用本地 http 服务加 playwright 或系统浏览器打开（file 协议常被拦）。
- 预览发布后，在对话里报一次**本轮生成消耗**：本轮 token（取本轮开始与结束时系统给出的剩余 token 差值，标注"估算"）、读了哪些库文件、是否联网、是否用子代理（子代理 token 单列）。数字放小表格，不写进页面。
- 此阶段**不改项目任何代码**。

### 4b. 用户不满意：换一批

第 3 步或第 4 步之后用户说"不满意 / 换一批 / 不是这个感觉"，走这里，不重跑第 1、2 步：

1. 先问一句方向（单选）：**太花** → 时长降一档、去掉装饰性配方；**太平** → 时长升一档、允许一个装饰性配方；**不像品牌** → 回第 2 步重判风格后再换；**换手法** → 风格不变，只换配方。
2. 从索引里取**未展示过**的配方重新组合 **3 套新方案（仍是两常规 + 一冲击）**，仍按视觉权重排，动效语言保持第 2 步的判定（除"不像品牌"）。取尽顺序：同风格行 → 相邻风格行 → 联网（走第 3 步的入库询问）。某个区块已无未展示配方时，该区块写"沿用上轮 <id>"或"本轮不加"并说明，不硬凑。
3. 预览页骨架不重画，只替换三套方案挂载的动效并重新发布。已展示 id 累加。发布后在对话里报本轮消耗与累计。
4. 换过 3 轮仍不满意，主动推荐一版**激进版**（比每轮都有的冲击版更进一步：冲击版仍在风格档内，激进版越出风格档），明确标注"激进版"并与上一轮并排预览：
   - 放宽：时长可越出风格档；每个高/中权重区块都可上装饰性配方；一屏同时运动的组数上限从 3 放到 5；允许持续循环类（流光、视差、辉光呼吸）；可叠加相邻风格行的手法（如奢华 + 活泼的弹性缩放）；同一区块可主推荐 + 备选同时挂。
   - 不放宽：只动 `transform` / `opacity`；每个动效带 reduced-motion 降级；首屏入场不阻塞 LCP；H5 不用 hover；低权重区块仍不加。
   - 配方仍先从库取（已展示过的可以重新组合叠加），库不够再联网并走入库询问。
   - 用户选激进版落地时，报告里单列"越出风格档的项"。
5. 激进版之后仍不满意，停下来问用户：是页面结构表判错了，还是风格判定有偏差，不无限换。

### 5. 列出实现方式，等用户选

按检测到的技术栈给 2–3 种可行方案，同一张表对比：

| 方案 | 适用场景 | 新增依赖体积 | 浏览器兼容 | 改动范围 | 维护成本 |

候选池（按栈取用）：

- 纯 CSS `@keyframes` / `transition` + `IntersectionObserver` 做滚动触发：零依赖，兼容最好，适合入场与 hover
- Web Animations API：需要 JS 控制时序、暂停、反向时用
- CSS 滚动驱动动画（`animation-timeline`）：视差与进度绑定，注意兼容
- 框架动效库：React 用 motion（framer-motion）、Vue 用 `<Transition>`/`@vueuse/motion`、跨栈用 GSAP；只在需要布局动画、手势、复杂编排时引入
- Lottie / Rive：插画类与品牌动画，需设计稿资源

给出你的推荐项与理由，然后**停下等用户选择**，不要替用户决定后直接开写。用户选了你不推荐的方案时，把顾虑说一次（体积、兼容、与既有动效库冲突等），再问一句"确认按这个做？"；用户确认就按用户选的做，不要换成自己的方案落地。

### 6. 落地与验证

用户选定后：

- 动效参数集中定义（CSS 变量或常量文件），不散写魔法数字
- 每个动效带 `prefers-reduced-motion` 降级
- 组件若双端共用，改动隔离到所选端（断点前缀、端判定条件或独立分支），另一端回归确认未变
- 改代码前先用 playwright 在所选端视口截一组"改前"图；改完再截"改后"图，逐个触发确认生效，两组图进报告作为加/不加的对比；H5 注意低端机帧率
- 报告：改动文件 / 动效清单与参数（含配方 id） / 改前改后截图对比 / 兼容降级说明 / 另一端未受影响的证据 / 未采纳的推荐及原因 / 本轮新入库的配方（如有）

## 配方库

`library/` 是本技能的本地知识储备，目的是少联网、少读文件：

- `index.md`：一行一个配方的索引，检索**只读这一份**；`entrance.md` / `scroll.md` / `hover.md` / `feedback.md` / `data.md` / `transition.md` / `ambient.md` 是正文，按 id 取 `### <id>` 到下一个 `### ` 之间的段落。
- 每个配方自带默认时长/缓动、性能标记、依赖和含 reduced-motion 降级的代码，可直接进预览页和落地代码。
- 用户随时可以新增：照 `_template.md` 填一段追加到分类文件，再在索引加一行，不用改本文件。字段取值见 `library/README.md`。
- 入库规矩：
  - **冲击版里用到的库外新手法，预览发布后默认直接入库**，不用问。按模板写成配方段追加到对应分类文件，索引加一行，在对话里列出新增 id。
  - 常规版里用到的、或联网搜到但最终没进冲击版的新手法，**先问用户**，同意才写。
  - 入库的配方必须是从预览里实际跑通的代码整理而来，不入库没验证过的手法。

## 红线

| 冲动 | 应该 |
| --- | --- |
| "PC/H5 一起做省事" | 单次一端，另一端另起一次 |
| "直接给每个区块加个 fadeInUp" | 先出结构表与权重，低权重不加 |
| 怕过头，推荐一堆 4px 位移、150ms 的微动效 | 默认给到肉眼可见的强度，由用户往下减 |
| 没看页面就推荐 | 先截图或读源码，推荐要引用具体区块 |
| 预览页把黑底页面做成了白底，或换了配色 | 保持现有 UI，只加动效；改背景或配色必须用户明确同意 |
| playwright 截出来什么色就用什么色 | 先核对 prefers-color-scheme / 主题类，以用户可见状态为准 |
| 跳过预览直接改代码 | 预览先行，用户看过再落地 |
| 用户说"随便，你定" | 仍给出方案对比与推荐项，由用户确认再写 |
| 用户选了我不认同的库，"我用更优的方案替他做了" | 说一次顾虑并请确认；确认后按用户选的做 |
| 为一个 hover 引入整套动效库 | 纯 CSS 能做的不引库 |
| H5 上推荐 hover 动效 | 换点击反馈或入场提示 |
| 动 `width`/`height`/`top`/`left` | 换 `transform`/`opacity` |
| 忘了 reduced-motion | 每个动效都要有降级 |
| 项目已有动效语言却另起一套 | 延续既有时长、缓动与手法 |
| 没查库就联网搜"最新动效趋势" | 先读 `library/index.md`，库不够再搜 |
| 为了省事一次 cat 整个 library | 只读索引，命中 id 再按段截取正文 |
| 常规版里的新手法"顺手写进库里" | 先问用户是否入库，同意才写 |
| 冲击版的新手法做完就忘了入库 | 预览发布后默认入库，对话里列出新增 id |
| 用户说换一批，"重新截图重新分析" | 结构表与风格判定沿用，只换配方、只换预览里的动效 |
| 换一批时把上轮的又推出来 | 已展示 id 全部排除 |
| 预览只放加了动效的版本 | 每套方案给"原始 / 动效"开关 |
| 预览拆成一个个区块小面板 | 整模块复刻，一次三套完整方案 |
| 三套只是同一强度的三个变体 | 两套常规 + 一套冲击版，冲击版写清成本 |
| 冲击版为了"冲击"把持续动效一直跑 | 离开视口暂停，reduced-motion 关闭 |
| 发布预览页后忘了报消耗 | 每次发布后在对话里给本轮与累计 token 估算，不放进页面 |
| 换了三轮还在同一档里挑 | 第 3 轮后主动给激进版，放宽时长档与装饰性限制 |
| 激进版顺手把 reduced-motion、LCP、只动 transform/opacity 也放了 | 这几条是底线，激进版也不碰 |
| 激进版之后还在无限换 | 停下问结构表或风格判定是否有偏差 |
