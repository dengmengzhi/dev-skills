# 新需求开发工作流

跨项目通用。项目专属规则不写在本技能里，而是在阶段 0 从项目自身的约定文件中读取。

## 适用边界

**走该流程**：有需求文档 / 原型 / Figma / 口述诉求的新需求或新功能，涉及新页面、新模块、跨多文件改动。

**不走该流程，直接做**：单文件改动、bugfix、纯文案或样式微调、依赖升级、无行为变化的重构。

## 阶段 0 · 摸清项目（每次必做，不可跳过）

不要凭记忆假设项目的技术栈和命令。

- 读项目约定文件：`CLAUDE.md`、`AGENTS.md`、`.cursorrules`、`README`、`CONTRIBUTING`。把其中的**硬规则**（禁止改动的目录、必须先查的 API、新增模块的多处联动清单、命名与分层约定等）逐条摘出来，写进设计文档专门一节，编码时当 checklist 用。
- 识别验证命令，来源按优先级：项目约定文件里明写的 > `package.json` scripts / `Makefile` / `pyproject.toml` / `Cargo.toml` > 通用默认。需要拿到四类：**格式化、类型检查、lint、测试**。缺失或有歧义时问用户，不要猜命令名。
- 识别文档落点：优先项目已有的 `docs/` 或 `doc/`，都没有则新建 `docs/`。
- 识别测试组织方式：与源码同目录（`*.test.ts`）还是独立 `tests/` 目录，跟随项目现状。

## 阶段 1 · 明确需求

- 读需求/原型文档，列出需求点与交互明细。**有歧义或缺失先问，不要自行假设。**
- 无文档时：与用户口述对齐需求点，确认后同样产出设计文档。
- 遵循项目既有架构整理落地方案：拆分需求细节、梳理可复用的既有模块、落地组件/模块设计、分析对现有功能的影响点。**优先复用和扩展，而非新建平行实现。**
- 涉及视觉界面时主动询问 Figma 链接，按模块拆分并把链接挂在对应模块设计下；无 Figma 则明确记录"按项目现有 UI 规范实现"。
- 涉及接口时确认接口状态：已就绪 → 确认契约与生成方式；未就绪 → 先定好 mock 数据契约，并在文档中标注为待联调。
- 产出设计文档 `docs/<需求名>_<YYYYMMDD>.md`，固定小节：
  1. 明确需求（需求点 + 交互）
  2. 需求框架图
  3. 项目硬规则（阶段 0 摘出的条目）
  4. 复用模块与扩展点
  5. 模块/组件设计（含各模块 Figma 链接）
  6. 影响点（受影响的既有页面/接口/公共模块）
  7. 任务清单（`- [ ]` checkbox，编码阶段逐条勾掉）
  8. 验收用例（阶段 4 逐条执行的依据）

**闸门：设计文档写完后停下，等用户确认，确认前不写任何业务代码。**

## 阶段 2 · 编码

- 动手前先跑基线（类型检查 + 测试）并记录结果。**大多数存量项目本身就有失败用例和 lint 报错，验收标准是"相比基线无新增失败"，不是绝对全绿。**
- 按任务清单逐条实现，每完成一条回写勾选（context 中断或 `/clear` 后据此续做）。
- 逐条遵守设计文档第 3 节的项目硬规则；涉及"新增某类模块需多处联动"的清单时，逐处核对，并提醒用户是否有配套的后端/配置改动。
- 用第三方库的 API 前先查实际版本的文档或类型定义，不凭记忆写。
- 抽象克制：同一逻辑出现两次以上才抽公共，否则与调用方同目录共存。
- 为核心逻辑补测试用例，跟随项目既有的测试组织方式和断言风格。

## 阶段 3 · UI 还原

仅在需求含视觉界面时执行，纯逻辑/后端需求跳过。

- 功能可跑通后再开始，不在功能未完成时提前抠像素。
- 有 Figma：用 `playwright-cli` 截图，与设计稿逐屏对比微调（间距、字号、色值、空态、加载态、错误态）。
- 无 Figma：按项目现有 UI 规范自检一致性，并可基于当前实现向用户推荐更合适的交互方式。

## 阶段 4 · 质量保证

用阶段 0 识别出的真实命令，按顺序执行：

| 检查 | 通过标准 |
| --- | --- |
| 格式化 | **必须限定到本次改动的路径**，跑全仓会重排大量无关文件、污染 diff |
| 类型检查 | 无新增错误（对比阶段 2 基线） |
| lint | 无新增报错（同样优先限定路径） |
| 测试 | 无新增失败（对比阶段 2 基线） |
| 验收用例 | 读设计文档第 8 节，逐条执行全部通过 |
| 影响点回归 | 读设计文档第 6 节，逐个验证未被破坏 |

任一项未通过就修到通过，或明确告知用户"这项跳过了 + 原因"，**不要含糊带过或谎报通过**。

## 收尾

- 输出：本次改动文件清单 + 各项验证结果（含与基线的差异）+ 遗留项（待联调接口、跳过的检查、已知限制）。
- **不执行 `git add` / `git commit` / `git push`**，改完停下，由用户自行 review 后提交。
